Enterprise mode adds authentication and access control to mcpjungle, but ongoing administration happens in the Dashboard.

Use the governance guides for the full operational model:

- [Access control](/governance/access-control)
- [Manage clients and users](/governance/clients-and-users)
- [Config file reference](/reference/config-file)

<Info>
  Commands on this page require the server to be running in enterprise mode with `mcpjungle start --enterprise`.
</Info>

<Note>
  Treat `mcpjungle <command> --help` as the authoritative source for current bootstrap flags. Legacy enterprise CLI management workflows for users, device tokens, permission groups, and client identities are no longer supported.
</Note>

## `init-server`

Initializes a fresh enterprise server.

```bash
mcpjungle --registry http://your-server:8080 init-server
```

Run this once against a new enterprise deployment. It creates the initial admin user, generates a one-time initial password, and stores the server URL in `~/.mcpjungle.conf`.

<Warning>
  This is a one-time bootstrap step. Store the generated bootstrap credentials securely.
</Warning>

## Dashboard workflow

Use the Dashboard for all ongoing enterprise administration:

- create pending users and share the one-time initial password
- require each user to change the password on first sign-in
- create permission groups and bind upstream MCP servers to them
- issue personal device tokens for each MCP client or device
- revoke device tokens when access needs to be removed

## Typical setup flow

<Steps>
  <Step title="Start the server in enterprise mode">
    ```bash
    mcpjungle start --enterprise
    ```
  </Step>

  <Step title="Initialize the server once">
    ```bash
    mcpjungle --registry http://your-server:8080 init-server
    ```
  </Step>

  <Step title="Open the Dashboard">
    Sign in as the initial administrator, then create pending users, permission groups, and personal device tokens.
  </Step>

  <Step title="Register upstream MCP servers in the Dashboard">
    Add the upstream servers you want the gateway to expose, then bind them to the appropriate permission groups.
  </Step>
</Steps>
