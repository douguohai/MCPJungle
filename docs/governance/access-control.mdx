---
title: "Control MCP client access"
description: "Create personal device tokens in the Dashboard and assign permission groups so each client can only reach the servers it should use."
---

In development mode, every MCP client connected to the gateway can access all registered servers.

In enterprise mode, access control is split between permission groups and personal device tokens.

The legacy `mcpjungle create mcp-client`, `--allow`, and `--access-token` CLI workflows are no longer supported.

## How access works

1. An administrator creates or updates a user in the Dashboard.
2. The administrator assigns the user to the permission groups that match the required upstream MCP servers.
3. The user creates a personal device token in the Dashboard for each device or client.
4. The client sends that token in the `Authorization: Bearer` header.

Example for Cursor or any other MCP bridge:

```json
{
  "mcpServers": {
    "mcpjungle": {
      "url": "http://localhost:8080/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_DEVICE_TOKEN"
      }
    }
  }
}
```

<Note>
  Device tokens are not login credentials. They only authorize MCP client requests to the gateway.
</Note>

## Rotate or revoke access

If a token is leaked or a device is retired, revoke that token in the Dashboard and create a replacement if needed.

<Warning>
  Do not reuse one device token across multiple tools or team members. Issue one token per device or workflow so rotation stays manageable.
</Warning>
