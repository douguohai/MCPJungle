---
title: "Manage clients and users"
description: "Manage human users, permission groups, and personal device tokens in Mcpjungle enterprise mode."
---

Enterprise mode separates human users from the personal device tokens used by MCP clients.

- **Users** are human operators who sign in with username and password through the Dashboard.
- **Personal device tokens** are the credentials MCP clients use to connect to the gateway on behalf of a user.

That separation keeps browser sign-in, client auth, and permission assignment clean.

## Users

Administrators create users as pending accounts in the Dashboard.

The Dashboard shows a one-time initial password when the user is created. The user must sign in and change that password before the account becomes active.

Standard users can inspect and use Mcpjungle according to the permission groups assigned to them. They do not get the same write capabilities as a system administrator.

## Personal device tokens

Create a personal device token for each MCP client or device from the Dashboard.

The token value is shown only once when it is created. Copy it immediately and send it in the `Authorization: Bearer` header from the client.

If a device is retired or a token is leaked, revoke the token in the Dashboard and issue a replacement.

## Permission groups

Permission groups determine which upstream MCP servers a user and their device tokens can reach.

See [Access control](/governance/access-control) for the main workflow.

## Recommended identity model

For a small to medium sized deployment:

- create a small number of admin users for platform operators
- create one user in Mcpjungle for each human operator who needs Dashboard access
- create one personal device token per consuming application or workflow
- avoid sharing one device token across multiple tools or teams

That keeps auditability and token rotation manageable without introducing needless process overhead.
