If you're an individual user running mpcjungle locally or for personal use (most likely in development mode), you can skip this section entirely.

The Governance model is useful for organizations running mcpjungle in a shared environment in the **enterprise mode**.

In enterprise mode, organizations want:

- Authenticated human access through the Dashboard
- Permission groups for upstream server access
- Personal device tokens for MCP clients
- Human users separated from machine identities

## Development mode versus enterprise mode

| Capability | Development mode | Enterprise mode                   |
|---|---|-----------------------------------|
| Gateway authentication | Disabled | Username/password in the Dashboard; `mcpj_session` for human users and personal device tokens for MCP clients |
| MCP client access control | Open access to registered servers | Permission groups control access |
| User accounts | Not needed | Supported                         |
| OpenTelemetry metrics | Disabled by default | Enabled by default                |
| Server initialization | Automatic | Manual initialization by an Administrator   |

## Governance model

Mcpjungle uses three main identity and access concepts in enterprise mode.

### Administrator

Admin initializes the server, registers MCP servers, and manages users, permission groups, and personal device tokens in the Dashboard.

### MCP clients

MCP clients are non-human consumers of the gateway. They authenticate with personal device tokens, including agents, CLIs like claude code, IDEs like Cursor, and custom agents.

Each client gets:

- a personal device token
- the server access granted by the user's permission groups

### Users

Users are human identities for people who need authenticated access to Mcpjungle. They sign in with username and password and receive an HttpOnly `mcpj_session` cookie.

## Typical enterprise flow

<Steps>
  <Step title="Start Mcpjungle in enterprise mode">
    Deploy the gateway in enterprise mode and connect it to MySQL 8.0.
  </Step>
  <Step title="Initialize the server">
    Run `mcpjungle init-server` once to create the initial admin identity.
  </Step>
  <Step title="Register MCP servers">
    Register the upstream servers you want the gateway to expose in the Dashboard.
  </Step>
  <Step title="Create users in the Dashboard">
    Create pending users, share the one-time initial password, and let each user change it on first sign-in.
  </Step>
  <Step title="Create permission groups and device tokens">
    Bind upstream servers to permission groups, then issue one personal device token per MCP client or device.
  </Step>
</Steps>

## Why this matters

For a shared deployment, a serious product needs more than just a gateway endpoint. It needs a control boundary:

- which client can reach which server
- which humans can operate the system
- how tokens are issued and rotated
- how usage can be observed centrally

That is what enterprise mode is for.
