# MCPJungle 企业版信息架构校准设计

## 目标

把当前以 MCP 协议对象为中心的后台，校准为内部团队可以直接理解和使用的企业 MCP Hub。用户先找到服务，再查看该服务的工具、提示模板、数据资源和连接状态；管理员通过用户、权限组和设备令牌控制访问；调用统计能够追溯到个人身份。

## 产品边界

- 仅保留企业模式，不在界面中暴露开发者模式概念。
- 数据库只支持 MySQL，不设计其他数据库的兼容入口。
- 不新增外部租户、计费、审批流或公开市场。
- 不为旧前端路由保留兼容页面；旧的能力类型一级入口直接收敛到服务详情。
- “工具组”不是权限模型，改名为“能力组合”，作为管理员高级能力保留。

## 信息架构

一级导航按用户任务分组：

1. 工作台：概览。
2. 服务中心：MCP 服务。
3. 个人接入：我的设备令牌。
4. 访问控制：用户、权限组，仅系统管理员可见。
5. 运行观测：调用统计，仅系统管理员和审计员可见。
6. 系统管理：系统设置；系统设置内提供运行诊断和能力组合入口，仅系统管理员可见。

不再把工具、提示词、资源、诊断作为平级业务模块。MCP 服务详情包含“概览、工具、提示模板、数据资源、连接诊断”五个页签。

## 关键页面

### MCP 服务列表

- 页面名称统一为“MCP 服务”，避免“服务器”让非技术用户误解为基础设施主机。
- 每行显示名称、传输协议、运行状态、工具/提示模板/数据资源数量和配置摘要。
- 名称可进入详情；操作区提供“查看详情”。
- 系统管理员可添加、启停和删除；其他角色只读。

### MCP 服务详情

- 顶部展示服务名称、状态、传输协议和配置摘要。
- 概览页签展示服务能力数量、更新时间和接入信息。
- 工具、提示模板、数据资源按当前服务过滤，表格不再重复“所属服务”。
- 连接诊断只解释当前服务的启用状态、发现状态、最近发现时间和脱敏连接信息。
- 能力为空时使用服务上下文中文空状态，例如“该服务暂未发现工具”，不提供命令行折叠区。

### 系统设置

- “运行诊断”展示系统版本、MySQL、主端点、传输协议和排查提示。
- “能力组合”说明其用途是把多个工具组合成独立调用端点，不与权限组混用。
- 两项均为管理员入口，不出现在普通成员主导航中。

## 权限与可见性

- `member`：概览、MCP 服务、自己的设备令牌。
- `service_admin`：在成员能力基础上查看服务详情；现有后端未提供细粒度服务管理授权前，不扩大写权限。
- `auditor`：成员能力加调用统计只读。
- `system_admin`：全部页面和管理操作。
- 路由权限和菜单可见性必须同时限制，不能只隐藏菜单。

## 文案与空状态

- 面向用户的名称统一使用“MCP 服务、提示模板、数据资源、连接诊断、能力组合”。
- 空状态以“当前发生了什么 + 下一步可执行动作”表达。
- 浏览器后台不重复展示 CLI 命令；命令行用法留在运维文档。
- 后端仍返回空状态结构，但前端以所在页面的中文上下文为准。

## 验收标准

- 普通成员看不到用户、权限组、系统设置、运行诊断和能力组合。
- 审计员能访问调用统计，但不能访问用户、权限组或系统设置。
- 系统管理员能从服务列表进入详情，并在五个页签之间切换。
- 工具、提示模板和数据资源只显示当前服务的数据。
- 旧的 `/tools`、`/prompts`、`/resources`、`/diagnostics`、`/tool-groups` 不再作为产品入口。
- 所有空状态为中文且不显示 CLI 折叠区。
- 前端 TypeScript 检查和生产构建通过；本地企业模式完成登录与主要路径人工验收。
