# 内部 MCP Hub 账户与授权说明

## 基本原则

- Web 管理端使用 8 小时服务端 Session Cookie，浏览器无法读取 Cookie 内容。
- MCP 客户端只使用个人设备令牌，不能拿 Web Cookie 调用 `/mcp`。
- 用户权限来自所有启用权限组关联服务的并集；没有权限组时默认无权访问任何服务。
- `restricted` 设备令牌只能在用户现有权限内继续收窄，不能扩大权限。
- 数据库只保存 Session 和设备令牌的 SHA-256 摘要，明文设备令牌仅在创建时显示一次。

## 使用流程

1. 系统管理员创建内部账户，系统返回一次性初始密码。
2. 用户用初始密码登录后必须先修改密码，账户才会变为 `active`。
3. 系统管理员创建权限组，将用户和 MCP 服务分别加入权限组。
4. 用户在个人设置中创建设备令牌，可选择继承全部权限或限定具体服务。
5. MCP 客户端使用 `Authorization: Bearer <设备令牌>` 调用 `/mcp`。

## 即时失效

- 禁用用户会在同一数据库事务中吊销其全部 Web Session 和设备令牌。
- 停用权限组、移除组成员或移除组内服务后，下一次 MCP 请求立即按新权限计算。
- 撤销或过期设备令牌返回 401，不会自动续期。

## 角色边界

- `system_admin`：账户、权限组和全局设置。
- `service_admin`：后续服务生命周期管理使用，不自动获得服务调用权。
- `member`：查看本人信息并管理个人设备令牌。
- `auditor`：后续审计只读页面使用，不自动获得服务调用权。

管理权限与 MCP 调用权限相互独立；任何角色要调用 MCP 服务都必须加入相应权限组。
