---
title: "Configure mcpjungle's database"
description: "Connect Mcpjungle to a MySQL 8.0 database using either a full DSN or MySQL-specific environment variables."
---

Mcpjungle requires a database to persist registered servers, tool groups, users, and related configuration. **MySQL 8.0 is the only supported database** — SQLite and PostgreSQL are no longer supported.

You can configure the connection with either a full DSN or individual environment variables.

## Option 1: Connection DSN

Set the `DATABASE_URL` environment variable to a full MySQL connection string:

<Tabs>
  <Tab title="Direct binary">
    ```bash
    export DATABASE_URL=mysql://admin:secret@localhost:3306/mcpjungle
    mcpjungle start
    ```
  </Tab>
  <Tab title="Docker">
    ```bash
    docker run -d \
      --name mcpjungle-server \
      -e DATABASE_URL=mysql://admin:secret@your-db-host:3306/mcpjungle \
      -p 8080:8080 \
      ghcr.io/mcpjungle/mcpjungle:latest
    ```
  </Tab>
</Tabs>

## Option 2: Individual environment variables

If you prefer not to construct a full DSN, set the individual MySQL variables instead. `MYSQL_HOST` is required; all other variables are optional and have sensible defaults.

```bash
# Required
export MYSQL_HOST=localhost

# Optional (defaults shown)
export MYSQL_PORT=3306
export MYSQL_USER=root
export MYSQL_PASSWORD=secret
export MYSQL_DB=mcpjungle

mcpjungle start
```

Each credential variable also accepts a `_FILE` variant, which reads the value from a file. This is useful for Docker secrets and similar secret-injection mechanisms:

| Variable | File variant | Default |
|----------|-------------|---------|
| `MYSQL_USER` | `MYSQL_USER_FILE` | `root` |
| `MYSQL_PASSWORD` | `MYSQL_PASSWORD_FILE` | _(empty)_ |
| `MYSQL_DB` | `MYSQL_DB_FILE` | `mcpjungle` |

Example using file-based secrets:

```bash
export MYSQL_HOST=localhost
export MYSQL_USER_FILE=/run/secrets/mysql_user
export MYSQL_PASSWORD_FILE=/run/secrets/mysql_password
export MYSQL_DB_FILE=/run/secrets/mysql_db

mcpjungle start
```

<Note>
  If both a variable and its `_FILE` counterpart are set, the plain variable takes precedence.
</Note>

## Character set and time zone

Mcpjungle expects MySQL to use the `utf8mb4` character set with the `utf8mb4_0900_ai_ci` collation. The Docker Compose files bundled with Mcpjungle enable these by default. If you manage your own MySQL instance, start it with:

```bash
mysqld --character-set-server=utf8mb4 --collation-server=utf8mb4_0900_ai_ci
```

Timestamps are written to MySQL in UTC.

## Variable precedence

When Mcpjungle starts, it resolves the database connection in this order:

1. `DATABASE_URL` — used as-is if set
2. `MYSQL_HOST` (+ optional `MYSQL_*` variables) — constructs a DSN if `MYSQL_HOST` is set
3. If neither is set, the server refuses to start

## Production recommendations

<Tip>
  Deploy a separate MySQL 8.0 instance (or a managed MySQL service) and supply its endpoint via `DATABASE_URL`. Running the database in a sidecar container is acceptable for development but not recommended for production.
</Tip>

The production Docker Compose file (`docker-compose.prod.yaml`) bundles a MySQL 8.0 container for convenience. For a real deployment, replace it with a managed database service and update the `DATABASE_URL` accordingly.
